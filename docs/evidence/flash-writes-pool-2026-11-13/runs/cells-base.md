## Draft questions

- In Open_Waiting_AtCap, when Put delivers a conn to a waiter and multiple waiters remain, how should the state be classified given connReqs is still non-empty?
- Release sets c.conns=nil and closes the channel, but connReqs waiters are never signaled; their Get blocks forever. What disposition should represent that?
- In Closed, Put calls c.Close(conn) but c.close has been set to nil, so Close returns nil without closing the conn; is the conn leaked and what disposition covers this?
- In Closed, Ping calls c.ping which is nil after Release; is the resulting nil-pointer panic 'handle' or 'UNSPECIFIED'?
- In Open_NoIdle_BelowCap, Close decrements openingConns and may push it below zero when no opening conns exist; how should this be classified?
- Are the state names sufficient given that openingConns counts active conns but idle channel length counts idle conns; can both idle>0 and openingConns>=maxActive coexist after Put/Close combinations?
