# Bounded gobreaker analysis

Read README.md and gobreaker.go in full. The initial report was saved before any probe ran. It contains 23 candidate findings. The final report contains 29 findings and retains questions where the documentation does not cover the actual ordering. No source, existing test, or configuration file was edited.

## Observed effects

- One completion can charge the same closed admission repeatedly. In half-open, two success reports from one admission can close a breaker configured for two trials. The next report from that old generation contributes no accounting. (observed-in-tests: analysis/_probe/identity_test.go:73 ("identityCounts(t, cb, Counts{Requests: 1, TotalSuccesses: 2, TotalFailures: 2, ConsecutiveFailures: 2})"), analysis/_probe/identity_test.go:87 ("identityState(t, cb, StateClosed)"), analysis/_probe/identity_test.go:90 ("identityCounts(t, cb, Counts{})")).
- An unresolved half-open admission continues to occupy capacity after the original caller leaves. A later matching success closes the breaker, and a matching failure starts a new open window. In the application waiter probe, a worker returned the original request pair to the application's buffer after the waiter departed, including when accounting was stale. (observed-in-tests: analysis/_probe/identity_test.go:104 ("identityRejected(t, cb, ErrTooManyRequests)"), analysis/_probe/identity_test.go:111 ("identityState(t, cb, StateClosed)"), analysis/_probe/identity_test.go:116 ("identityRejected(t, cb, ErrOpenState)"), analysis/_probe/identity_test.go:797 ("if got := <-delivered; got != reply {")).
- Reporting can first advance a timed-out open breaker and send a notification, then skip stale accounting. Counts reads stored counters without advancing expiry. README.md:77–79 explicitly covers discarding pre-reset accounting. The ordering and callback eligibility remain open. (observed-in-code: gobreaker.go:220 ("return cb.counts"), gobreaker.go:298 ("state, generation := cb.currentState(now)"), gobreaker.go:299 ("if generation != before {"), gobreaker.go:342 ("cb.setState(StateHalfOpen, now)"), gobreaker.go:359 ("cb.onStateChange(cb.name, prev, state)")).
- Execute can charge a failure twice when ReadyToTrip panics and the generation remains current. A reporting panic can also replace the panic that triggered reporting. State transitions are committed before OnStateChange; a sufficiently slow panicking open notification allowed Execute's fallback to trigger half-open notification. (observed-in-tests: analysis/_probe/identity_test.go:354 ("identityCounts(t, cb, Counts{Requests: 1, TotalFailures: 2, ConsecutiveFailures: 2})"), analysis/_probe/identity_test.go:378 ("identityPanic(t, func() {"), analysis/_probe/identity_test.go:472 ("if len(notifications) != 2 || notifications[0] != StateOpen || notifications[1] != StateHalfOpen {")).

## Checks

- One draft-verify request using jev-1.14.0 for verification. The tool used DeepSeek Flash for extraction with max-tokens 12000. Reviewed 34 draft claims and 20 draft questions. One final Jev batch returned 78 supported and 15 unclear verdicts for 93 independently cited parts. The review records each draft and final verdict, including manual tracing where the fragment alone was insufficient.
- Ran `go test -race -count=3 -timeout=30s -json -overlay analysis/overlay.json -run '^TestIdentity' .`. Attempt 01 passed with 19 distinct top-level tests and 57 starts. Attempt 02 added probes for closed expiry during panic retry, half-open notification panic, and application waiter departure. It passed with 22 distinct top-level tests, 66 starts, and 213 passing test/subtest events. Both stderr captures were empty. Both attempts are retained.
- Ran `python3 validate_report.py analysis/initial.json analysis/final.json`. Both files passed shape and source fragment validation. This validator does not assess semantics.

## Limits and changes after review

- The mutex protects the state and accounting steps within one report. Execute's fallback is a second acquisition. The relative order between that acquisition and a contending operation was analyzed from source. No data race finding was retained. (observed-in-code: gobreaker.go:237 ("cb.afterRequest(generation, false)"), gobreaker.go:294 ("cb.mutex.Lock()"), gobreaker.go:295 ("defer cb.mutex.Unlock()"), gobreaker.go:299 ("if generation != before {")).
- The draft's suggestions that Counts advances expiry, rejected admissions fail to return their internal generation, and a half-open failure merely resets a streak were corrected in review. The two expired-state checks are distinct switch arms. No exact timestamp equality was forced. (observed-in-code: gobreaker.go:220 ("return cb.counts"), gobreaker.go:284 ("return generation, ErrOpenState"), gobreaker.go:286 ("return generation, ErrTooManyRequests"), gobreaker.go:330 ("cb.setState(StateOpen, now)"), gobreaker.go:335 ("switch cb.state {"), gobreaker.go:337 ("if !cb.expiry.IsZero() && cb.expiry.Before(now) {"), gobreaker.go:341 ("if cb.expiry.Before(now) {")).
- The probes ran on Go 1.27.3 darwin/arm64. Same-breaker synchronous reentry, counter wrap, and concurrent receiver reassignment were not runtime tested. The application harness chose a buffered result channel so delivery remained observable after its waiter departed. The breaker has no knowledge of that channel (inferred from its synchronous request call and return). (observed-in-code: gobreaker.go:242 ("result, err := req()"), gobreaker.go:244 ("return result, err")).
