## Admission, delivery and identity

- **A.** The pointer receiver identifies the original Port. Admission increments the account then in its Target field and saves that account's numeric Epoch. At each delivery A reads Target on that same Port, compares the current occupant's Epoch, and credits that occupant if equal. A distinct same-epoch account can receive a success with zero requests of its own. A different epoch skips credit, and a nil target panics on the epoch read. In N02, switching only the caller's Port variable leaves the first delivery on the original account. Mutating Target through the old Port alias redirects the next delivery to the matching-epoch account. [Source](../component.go#L7) · [Probe](./_postprobe/binding_test.go#L38)
- **B and F.** Admission copies the Account pointer out of the Port and increments Requests through that pointer. Each delivery increments the captured account's current Successes. Target mutation, detachment, or a change to the captured account's Epoch leaves attribution intact. N01 isolates a different operation from the preserved F replacement case. The caller reassigns only its local pointer to a distinct Port and Account. The old Port still points to the original account before and after delivery. The original goes from (1 request, 0 successes) to (1, 1), and the replacement stays at (0, 0). B's preserved reset case shows that the callback uses the account's current fields through the saved pointer. [B source](../component.go#L12) · [F source](../component.go#L30) · [F probe](./_postprobe/binding_test.go#L9) · [Reset probe](./_probe/identity_test.go#L324)
- **C.** Admission saves the Account pointer and its numeric Epoch and increments that account's Requests. Delivery reads Target from the original Port and first checks pointer equality. Only if it matches does the callback compare the saved Epoch to the admitted account's current Epoch. Credit goes to that admitted account. A nil or distinct target fails the first check. N03 shows that reassigning the caller's Port variable permits credit through the unchanged original Port, while redirecting the old Port to a third same-epoch account blocks the next credit. N05 shows that even a copy with identical Account fields fails pointer equality. After restoring Target and overwriting the admitted Account in place at its original address with the saved Epoch, delivery increments its current Successes from 10 to 11 while Requests remains zero. [Source](../component.go#L17) · [Retained Port probe](./_postprobe/binding_test.go#L38) · [Copy and overwrite probe](./_postprobe/binding_test.go#L107)
- **D.** Admission credits the account at the input key and retains the original Registry pointer and the string value of that key. Each delivery looks up the original key in that Registry's current Entries field and credits any non-nil occupant regardless of Epoch. In N04, reassigning the caller's key variable and then its Registry variable to a distinct Registry with a separate map leaves the first two deliveries on the original occupant. Mutating the saved key's entry through the original Registry alias redirects the third delivery. F42 separately swaps the entire Entries map on that Registry. A shallow Registry copy would share the map until either Entries field is reassigned, so entry mutation via a shared map can still change the retained Registry's lookup. That shallow-copy distinction follows from the source and was unprobed. [Source](../component.go#L5) · [Admission and delivery](../component.go#L22) · [Saved key probe](./_postprobe/binding_test.go#L73) · [Map replacement probe](./_probe/identity_test.go#L200)
- **E.** The value receiver is a shallow Port copy. Its Target pointer at admission still identifies the same Account, and delivery accesses that Account through the retained receiver copy. The external caller copy in F65 is a separate Port value. The preserved test calls E on the first Port, edits both caller-visible copies, and observes credit on the shared admitted Account. For A and C, a separate Port copy also initially shares the Account pointer, but changing the copy's Target does not edit the retained Port. This last distinction follows from the receiver types and the one-field Port definition. [Port definition](../component.go#L4) · [A source](../component.go#L7) · [C source](../component.go#L17) · [E source](../component.go#L26) · [Copy probe](./_probe/identity_test.go#L309)

The closures contain no request rollback, wrapper or key cleanup, or consumed flag. With no delivery the probes observe the admission counters alone. A credited invocation can be repeated, and A, C and D reevaluate their current gates on each call. Recovery after A's nil-target panic occurs in the probe. Restoring the binding permits a later call. C still needs both guards after restoration, while D can resume credit when a non-nil occupant reappears. These are observable counter effects and eligibility checks. Callback reachability and memory reclamation were outside the probe assertions. ## Qualifications and probe scope

- F07–F18, F53–F58 and F67–F72 use generic Port-or-Registry wording. Each Port path edits Target on the caller-visible Port used for admission. D changes the value stored under the saved key in the original Registry's map. These rows have no wrapper replacement or local variable reassignment step. The overlap cases keep two callbacks outstanding and deliver them in sequence. The caller-departure cases compare a run with no later invocation to a run with manual delivery after a binding change. There is no waiting-client or cancellation signal in those probes. The source establishes that the nil dereference occurs in the admission increment before a callback can return. F65's external caller copy is distinct from the value receiver that E retains. F66's probe assigns Successes=10 from its initial zero and explicitly resets Requests to zero. A separate Successes reset is absent from the probe. F74's two conditions are delivery-time guards against the pointer and epoch saved at admission.
