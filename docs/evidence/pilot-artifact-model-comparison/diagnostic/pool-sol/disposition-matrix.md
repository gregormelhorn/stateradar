Abstraction: pool publication, detachment and pending queue coexistence. Open has no queued request and either buffered or empty idle storage. Open_Waiting has pending requests without buffered idle entries. Open_WaitingWithIdle has both. Released and Released_Waiting distinguish whether pending entries survive. Guard alternatives distinguish instantaneous counts, channel readiness, callback phases, drain activity and per-call ownership tracks. Initializing includes the unreturned constructor. Released_Waiting is a lifecycle sink, with full rows preserving callable API effects.

## Guard notes

- G-01–G-04 constructor: inequalities are inclusive. Missing Factory or Close rejects; missing Ping is legal; nil Config crashes before guard. Proven Boolean and integer groups.
- G-05–G-07 Get admission: failed receive precedes mutex. At or above MaxCap enqueue, below MaxCap check Factory then call it. Runtime readiness proof is unproven (dynamic-state). Capture nil, received nil and nil Factory branch are proven Boolean partitions.
- G-08–G-10 candidate: timeout disabled at zero and below. Age strictly after the deadline expires. Ping presence and error select discard versus return only for buffered entries. Clock comparison and callback effects are unproven. An expired handoff loops to channel observation.
- G-11–G-13 Put: nil interface rejects. Detached calls Close. A positive queue length selects handoff irrespective of idle capacity; zero selects a nonblocking channel attempt. Ready/full race is unproven (dynamic-state). At capacity zero there is no idle buffering.
- G-14–G-17 Close/Ping/Release/request: nil interface rejects, Close callback nil skips decrement, Release capture nil skips drain. Request receive with ok false returns the literal sentinel. State guarantees for callback and delivery outcomes are qualified in guard-results.txt.
- Pair reachability: P-01a and P-03a. No two-target encoding is needed for Release because pending presence is known in each row.
