# DeepSeek Flash as the Pool pilot controller

Flash steered Part A on Pool `6084537` with Jev 1.14.0 as a verifier.
The historical comparison is the [matched Codex run](../pool-flash-writes-matched/README.md)
with the same source, selective output and the v1.25 prompt. The prior
Codex reference used Flash for Part B. The Flash controller runs target
a separate Codex Part B session with the inspected blind package.

The unchanged and revised runs used the same controller, tool surface
and disabled thinking after the initial high-thinking attempt hit its
8,192-token response cap. The full v1.26 prompt added a sweep inside
operations and early artifact checks. The separate checkpoint arm
also received the [checkpoint brief](checkpoint-brief.txt). Both main
Flash runs initially lost a provider response and then continued in
a fresh Flash context from existing artifacts using the
[recovery brief](recovery-brief.txt). The protocol and all prompt
variants are retained.

Historical P-04a is a particular schedule. A Get misses the idle
channel at capacity. Before it obtains the lock, Put buffers a returned
connection. Get then queues without checking the idle channel again.
A newer Get takes the idle value while the first remains parked until
another Put. The v1.25 Q-20 explicitly covers buffering before a
pending append and the resulting blocked caller. It does not trace the
new caller or later handoff. The v1.26 trace named P-04a concerns two
Put calls on one value. Its P-03a/b cover Put after enrollment and Put
before Get begins. Neither covers the intervening schedule.

The final main-arm sidecars regenerated byte-for-byte on fresh copies,
and all five gates passed again. Before recovery the v1.25 model briefly
edited the generated sidecar by hand, leading to an apparent green
reachability result while its source artifacts still failed. The final
verification used independently regenerated files. The final v1.26
directory used a fresh Flash blind fallback after the initial bridge
refused its scratch directory. A repaired bridge ran Codex separately
on the final v1.26 package in an audit copy, giving 49/49 covered
keys and all five gates green. The Flash-written diff belongs to its
own blind fallback. The external audit verifies coverage and does
not attribute the fallback's classifications to Codex.

The Codex reference reported the original TestPool_Get timeout and a
separate Go race-detector finding. Flash v1.25 also recorded the
upstream timeout. Flash v1.26's suite run hit a fixed-port collision,
and its already-executed public harness supplied narrower evidence.
The attempted runs overlapped in wall time and shared the suite's
hard-coded RPC port. The five pack gates cover generated artifacts.
They do not establish equal test or finding coverage.

## Prompt observations

The incremental rule produced useful v1.26 artifacts sooner, even
though the two finished runs required substantial correction. Repeated
failures clustered around malformed JSON tool arguments, embedded Go
string literals, Markdown citation delimiters, compound state names,
repository-relative test paths, and required headings. The recovered
v1.26 run regenerated the matrix citations from the Markdown. Both
runs spent more than 100 commands matching a broad parser-debug pattern.
Use the authoring contract and representative accepted artifacts to
prevent this work before the full matrix is written.

Three independent, source-only diagnostics tested generic window
prompts. The [first](window-probe.txt) found the stale empty observation
and the under-capacity factory branch. The [second](window-branch-probe.txt)
identified the stale-read window and the at-capacity guard independently,
but failed to carry the newly idle resource through the waiting branch.
The [third](window-product-probe.txt) decomposed the schedule into a
product but anchored it to channel nilness, excluding Put as a mutator
of the selected predicate. None recovered the full historical P-04a,
and the returned source analyses included other unverified claims.

The additional checkpoint arm stopped at two of five gates. Matrix and
guard execution passed. The sidecar and reachability checks failed,
and the blind table was absent. A concrete counterexample to taking
the model at face value was its claimed retry after Factory returns an
error. The code unlocks and returns that error at channel.go:155-157.
The operator ended this exploratory arm after repeated repair loops
rather than count it as a completed pilot. Its metered steering cost
was $0.299768, and the bounded-tool ledger added $0.026491. One
unresolved reservation of $0.349944 is excluded. It named both same-caller
acquisitions but did not recover the exact historical P-04a.

## Recommendation

Keep Codex as the steering reference. Use Flash for bounded source
extraction and for candidate schedules, with Jev checking exact claims
and the existing deterministic checks deciding artifact validity.
Test a structured schedule table before another full Flash pilot.
Have it enumerate each readiness observation, the writers that can
interleave before commit, and the resulting branch on both sides of
capacity thresholds. Require branch witnesses with concrete return,
wait, inventory and handoff effects. Compile and test one such schedule
before generalizing. Render the matrix from typed fields and validate
one generated cell, a pair citation and a guard group before scaling
to the whole grid. Use fresh contexts at stage boundaries so parser
repair cannot crowd out review.

Re-evaluate on Pool plus a second component held out from prompt
tuning. Compare source-trace completeness and executed reproductions
against an independently reviewed control set. Record provider costs,
time to acceptance and fallback frequency. A five-gate pass, cheaper
model tokens or a similar question count alone is insufficient to
promote Flash to the default controller.
